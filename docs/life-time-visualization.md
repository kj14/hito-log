# 人生時間可視化システム 設計ドキュメント

## 1. 背景と目的
- **課題認識**: 人は日々の有限な時間を実感しづらく、惰性で過ごすことで人生の優先事項に時間を投資できない。
- **提供価値**: 生命時間・人間関係・目標達成の 3 軸で時間を可視化し、意図的な行動計画を後押しする。
- **成功イメージ**: ユーザーが「誰と・何に・いつまでに」時間を使うかを自律的に決定し、継続的な振り返りが習慣化している状態。

## 2. ターゲット像
| ペルソナ | 特徴 | 求める価値 |
|----------|------|-------------|
| 自己成長志向の社会人 | 20〜40 代、学習／副業に時間を投資したい | 目標達成までの必要時間・進捗可視化 |
| 家族との時間を大切にしたい親 | 子育てと仕事の両立で時間が不足 | 一緒に過ごせる残り時間の把握と計画 |
| 人生設計を再考したいシニア | 退職後の生活を再設計中 | 残り時間とやりたいことの棚卸し |

## 3. 体験コンセプト
1. **Life Countdown**: 平均寿命をベースに現在までの消費時間と残り時間をリアルタイム表示。
2. **Relationship Sharing**: 登録した相手との「残り共有時間」「残り会える回数」を可視化。
3. **Goal Tracking**: 目標達成に必要な総工数と現状ペースを提示し、達成可能時期を予測。
4. **Scenario Simulation**: 頻度・投入時間の変更による影響を直感的に比較。

## 4. ユーザージャーニー
### 4.1 ファーストタッチ
1. LP から「時間の電池」コンセプトを理解。
2. メール／SNS 認証でアカウント作成。
3. 生年月日・性別・国籍・ライフスタイル質問に回答。
4. 個人ダッシュボードで残り時間と初期ハイライトを確認。

### 4.2 日次利用
1. 朝：ダッシュボードで残り時間と本日の提案行動を確認。
2. 日中：会った人・取り組んだ目標をアプリまたはウィジェットで記録。
3. 夜：振り返り通知から「今日の時間配分」と「明日の推奨タスク」を確認。

### 4.3 週次レビュー
1. 関係ごとの共有時間ランキングを確認。
2. 目標別の進捗差分とシミュレーションをチェック。
3. 次週の予定に反映（カレンダー連携やタスクリストにエクスポート）。

## 5. 情報アーキテクチャ
- **ホームダッシュボード**: 人生残り時間ゲージ、今週の関係ハイライト、目標進捗カード。
- **関係ハブ**: 登録相手一覧、残り時間ヒートマップ、シナリオ比較。
- **目標ハブ**: 目標カード、必要ペースの提示、バーンダウンチャート。
- **インサイト**: 月次レビュー、時間配分の偏り、アラート（残り会える回数の少ない相手など）。
- **設定**: ライフスタイル補正、通知制御、データインポート／エクスポート。

## 6. ドメインモデル
| エンティティ | 主要フィールド | 説明 |
|---------------|----------------|------|
| `users` | id, email, name, birth_date, sex, country, lifestyle_profile, timezone | ライフスタイルプロフィールには睡眠時間や喫煙習慣などの補正要素を格納。 |
| `life_expectancy_stats` | country_code, sex, age, expectancy_years, source | 公的統計を元にした年齢別平均余命テーブル。 |
| `relationships` | id, user_id, name, relation_type, birth_date, expected_lifespan_years, meeting_frequency, avg_session_minutes, intimacy_score | `meeting_frequency` は枚挙型（daily/weekly/monthly/custom）。 |
| `relationship_sessions` | id, relationship_id, scheduled_at, occurred_at, duration_minutes, channel, memo | 実際に会った記録と予定の差分を計測。 |
| `goals` | id, user_id, title, category, target_effort_hours, target_date, difficulty_level, motivation_notes | `difficulty_level` は主観評価で予測精度向上に利用。 |
| `goal_logs` | id, goal_id, logged_at, effort_minutes, quality_score, note | 質的評価を加味したペース補正が可能。 |
| `scenarios` | id, owner_type (relationship/goal), owner_id, parameters, outcome_snapshot | シミュレーション結果の保存。 |
| `integrations` | id, user_id, provider, scopes, metadata | カレンダーやウェアラブルとの連携定義。 |

## 7. 主要計算ロジック
- **残存寿命**: `life_expectancy_stats` から現在年齢における平均余命を取得し、ライフスタイル係数で補正。
  - `remaining_seconds = (expectancy_years * 365.25 * 24 * 3600) - elapsed_seconds`。
- **共有可能時間**:
  - `pair_remaining = min(self_remaining_seconds, other_remaining_seconds)`。
  - `shared_time = pair_remaining * meeting_frequency_factor * avg_session_minutes / 60`。
  - `meeting_frequency_factor` は週 1 回なら `1/7`、月 1 回なら `1/30` 等。
- **残り会える回数**: `pair_remaining_days / meeting_interval_days`。
- **目標必要ペース**: `required_daily_minutes = (target_effort_hours*60 - actual_logged_minutes) / remaining_days`。
- **予測完了日**: 実績ペース `avg_daily_minutes` が一定と仮定し、`remaining_minutes / avg_daily_minutes` を未来日に換算。
- **シナリオ比較**: 入力変更前後の KPI 差分（完了予定日、会える回数、充当比率）を算出し差分ハイライト。

## 8. UI／ビジュアル案
| コンポーネント | 概要 | 表示メトリクス |
|----------------|------|----------------|
| ライフバッテリー | 円形ゲージ + 数値カウントダウン。重要節目で色変更。 | 消費率・残り年数・今日の残り時間 |
| デュアルタイムライン | 自分と相手の寿命曲線を重ねて共有期間を着色。 | 残り共有時間、推奨会合頻度 |
| 目標バーンダウン | 横軸：日付、縦軸：残工数。現在ペースとの差を面グラフで表示。 | 予定 vs 実績のギャップ |
| 時間配分サンキー図 | 自己／仕事／家族／自己投資などカテゴリ別に時間の流れを可視化。 | 割合・増減トレンド |
| アラートカード | 「母との残り会える回数：あと 12 回」など行動喚起。 | 閾値を下回った KPI |

## 9. 非機能要件
- **リアルタイム性**: カウントダウンは 10ms 単位で UI 更新。バックエンドは 1 分ごとに再計算して差分のみ配信。
- **可用性**: 目標は 99.5% 稼働。データ損失リスクを軽減するため毎時バックアップ。
- **セキュリティ**: Supabase の RLS をベースに、関係データはデフォルト非公開。共有時はスコープ付きトークンでアクセス制御。
- **パフォーマンス**: 関係 200 件、目標 100 件までを想定し、主要 API 応答は 200ms 以内。
- **アクセシビリティ**: カラーコントラスト 4.5:1、キーボード操作、スクリーンリーダー対応の ARIA 属性を実装。

## 10. 技術アーキテクチャ方針
- **フロントエンド**: Next.js App Router + TypeScript。リアルタイム UI は `requestAnimationFrame` と `BroadcastChannel` で同期。
- **状態管理**: Supabase クライアント + React Query。キャッシュ無効化はイベント駆動。
- **バックエンド**: Supabase Postgres + Edge Functions。計算負荷の高いシミュレーションは Edge Function で実行。
- **ジョブ管理**: Supabase Scheduler を用いた日次・週次のリマインダー配信。
- **外部連携**: Google Calendar、Apple HealthKit、Oura Ring などへの拡張性を REST / Webhook で確保。

## 12. 成功指標
- **Activation**: 初回登録後 24 時間以内に「関係追加 + 目標追加」を完了した割合 60% 以上。
- **Engagement**: 週 3 回以上ログを記録するアクティブユーザー比率。
- **Retention**: 30 日継続率 35% 以上。リマインダー施策で +5pt を目標。
- **Outcome**: 月次アンケートで「時間の使い方が改善した」と回答したユーザー 70% 以上。

## 13. リスクと対応策
| リスク | 影響 | 緩和策 |
|--------|------|--------|
| 残り時間表示による不安感 | 利用継続率低下 | トーン＆マナーを柔らかく、ポジティブな提案を添える。非表示オプションを提供。 |
| ライフスタイル補正の精度不足 | KPI の信頼性低下 | シンプルな係数から開始し、ユーザーフィードバックでモデルを調整。 |
| 入力負荷の高さ | 初期離脱 | ガイド付きオンボーディング、外部カレンダー取り込み、ウィザード形式で段階入力。 |

## 14. 今後の検討事項
- SNS 公開データを活用した「憧れの人に会うまでの残り時間」提案の実現性。
- 営業活動への転用（案件パイプラインの時間シミュレーション）における共通化できるモジュール。
- やりたいことリスト（バケットリスト）のスケジューリング機能と既存カレンダーツールとの統合 UX。
